# Agent 网关中台：项目规格

## 1. 产品目标

构建一个供多个 Agent 项目共用、可通过公网访问的 AI 能力网关。调用方使用项目 API Key 访问统一接口；管理员通过 Web 控制台管理项目、密钥、提示词模板和记忆，并查看用量、费用与调用日志。

第一版优先证明下面这条端到端流程真实可用：

> 用户创建项目 → owner 申请 LLM 服务并获得首期月额度 → 创建项目 API Key → 调用兼容 OpenAI 的聊天接口（无需传项目 ID）→ 网关按项目服务权限和月额度调用 Mock Provider → 返回结果并记录不含正文的 token 日志。

## 2. 用户与权限边界

系统包含三类身份，认证方式不得混用：

- 唯一管理员：登录 Web 控制台，使用短期访问令牌管理所有项目、普通用户和运营数据。
- 普通用户：账户保存在数据库中；第一版的具体权限在 UI 和 API 契约阶段继续收敛，默认不能执行管理员操作。
- Agent 客户端：使用项目 API Key 调用 `/v1/*` 能力接口，只能访问该 Key 所属项目允许的能力和模型。

唯一管理员支持通过服务端 `.env` 引导创建，但管理员环境变量不是后续启动的必填项。启动规则如下：

1. 同时配置管理员用户名和密码时，环境变量是本次启动的权威值。服务在单个事务内创建唯一管理员，或更新数据库中已有管理员的用户名和密码哈希。
2. 两项都未配置时，服务读取并使用数据库中已有的唯一管理员，不修改其用户名和密码。
3. 两项都未配置且数据库中没有管理员时，启动失败，并提示需要完成首次管理员引导。
4. 只配置用户名或只配置密码时，配置无效，启动失败。

数据库约束保证最多只有一个管理员；如果检测到无法自动安全修复的多管理员异常，启动失败并给出不含敏感信息的诊断，不得静默删除账户。其他用户只通过业务流程写入数据库，不由环境变量同步。

第一版为单组织、多个项目，网关暴露公网。项目之间必须数据隔离；项目可设为公开或私有，公开项目对已登录用户只读开放。组织级多租户、公开注册、支付结算和复杂 RBAC 暂不实现，但领域模型和查询接口不得阻碍后续扩展。

## 3. 第一版范围

### 必须完成

1. 管理员登录。
2. 项目创建、停用和查询。
3. API Key 创建、列表、撤销；owner/editor 可随时查看完整 Key，数据库保存 HMAC 摘要与加密密文，不保存明文。
4. OpenAI 风格的 `POST /v1/chat/completions`，同时支持普通响应和 SSE 流式响应。
5. 模型路由采用 Provider Adapter；所有涉及第三方的接口第一版使用可重复测试的 Mock Provider，不阻塞主流程开发。
6. 每次调用生成 `request_id`，记录项目、Key、模型、状态、延迟和 token 用量；暂未配置价格时费用为空。
7. Dashboard 支持按项目和时间范围查看调用次数、成功率和 token；费用为空时前端显示 `-`。
8. 调用日志支持筛选、游标分页和详情查看；不得保存 API Key、Authorization、用户密码或上游密钥。
9. 提示词模板与记忆文件的固定目录视图及单文件增删改查。
10. Docker Compose 本地启动、数据库迁移、基础 CI 和可执行文档。

### 后续版本

- 选择并接入第一家真实 LLM Provider。
- Embedding、ASR、TTS 的真实 Provider 接入。
- 预算、配额、分项目限流、熔断和降级策略。
- pgvector 语义检索与长期记忆召回。
- 完整 OpenTelemetry 链路和生产级告警。
- 多组织、细粒度 RBAC、外部计费或支付。

## 4. 关键用户流程与验收

### 流程 A：创建项目和 Key

项目 owner/editor 可随时查看所属项目的完整 API Key；owner 可创建和撤销，editor 只读。撤销后再次调用必须返回结构化的 `401 invalid_api_key`。

### 流程 B：代理聊天调用

客户端携带项目 Key 调用聊天接口。系统验证 Key、项目状态和允许模型，向 Provider 转发，并返回兼容约定的结果。成功或失败均产生调用记录；上游超时、限流和不可用分别映射为稳定的网关错误码。

### 流程 C：查询用量与日志

管理员按项目和时间范围查询。Dashboard 汇总值应与调用记录一致；列表分页稳定；点击记录可查看请求元数据和错误摘要，但看不到敏感 Header、密钥、用户提示词或模型回复正文。

### 流程 D：管理模板和记忆

管理员进入项目资源页，左侧看到固定目录树，目录本身只读且不可新增、重命名或拖拽。点击文件进入文件模式，可以新增、编辑和软删除文件。并发编辑使用版本号或 ETag 检测冲突，冲突返回 `409 version_conflict`。

## 5. 固定资源目录

目录是业务分类的视图，不映射为服务器任意文件路径：

```text
Projects/{project_id}/
├── memory/
│   ├── sessions/
│   ├── profiles/
│   └── longterm/
└── templates/
    ├── system/
    ├── user/
    └── assistant/
```

目录由后端枚举生成。文件内容存储在数据库中，所有资源查询必须包含当前项目隔离条件。URL 使用稳定的 `project_id`，显示名称不得作为路径标识。

## 6. 技术基线

- 后端：Python 3.11+、FastAPI、SQLAlchemy 2、Alembic、Pydantic 2、asyncio/httpx。
- Python 工具链：`uv`、`pyproject.toml`、`uv.lock`、ruff、mypy、pytest。
- 数据库：PostgreSQL 16；需要语义检索时再启用 pgvector 和向量索引。
- 前端：React 18、TypeScript、Vite、Ant Design、Zustand、ECharts。
- 前端工具链：锁定 Node LTS 和一种包管理器，提交 lockfile；Vitest、Testing Library、Playwright、ESLint、Prettier。
- 部署：Docker、Docker Compose。
- 可观测：结构化日志；Prometheus 指标和 OpenTelemetry 按里程碑逐步接入。

前端必须从 OpenAPI 生成或共享类型安全的 API Client，不得在各页面自行拼接 URL 和猜测响应字段。

## 7. 后端分层

依赖方向固定为：

```text
HTTP API → Application Service → Domain Port ← Infrastructure Adapter
```

- API 层只处理认证、协议转换、输入校验和响应映射。
- Application Service 编排用例、事务和业务规则。
- Domain Port 描述项目仓储、Key 校验、Provider 调用、计价和审计能力。
- Adapter 封装 PostgreSQL、模型提供方、时钟和其他外部依赖。
- 配置和依赖装配只发生在组合根。

模型提供方不得直接散落在路由或业务服务中。Provider 接口至少描述非流式调用、流式事件、超时、取消、用量和错误分类。

## 8. 核心数据原则

具体表结构在 OpenAPI 和领域模型稳定后由 Alembic 迁移生成。至少包含：

- `projects`：稳定 UUID、名称、状态、能力和模型策略、时间戳。
- `api_keys`：项目、名称、不可逆 HMAC 摘要、加密密文、前缀、末四位、状态、过期时间、最近使用时间。
- `gateway_requests`：一次网关请求的状态、延迟、Provider、模型、错误分类和追踪标识。
- `usage_records`：输入/输出 token 或其他计量单位、Provider 原始用量。
- `cost_records`：可空费用、币种、单价版本、计价单位和最终费用快照。第一版币种为人民币；没有价格配置时不产生金额，API 返回 `null`，前端显示 `-`。后续从版本化 JSON 价格表读取不同模型单价，历史费用不得因价格表变化而重算。
- `resources`：项目、资源类型、固定分类、名称、内容、版本、软删除时间。
- `audit_logs`：管理员对项目、Key 和资源的管理操作。

调用日志、审计日志和应用运行日志是不同概念。数据库主要保存可查询的调用与审计事件；高频运行日志默认输出到标准输出，避免请求链路同步写大量日志拖慢代理。

日志保留规则采用并集：保留所有最近 30 天的数据，同时保证全系统最新 10,000 条数据始终保留。因此当最近 30 天不足 10,000 条时，会继续保留更早的数据，直到达到 10,000 条；当最近 30 天超过 10,000 条时，最近 30 天的数据全部保留。清理任务需可重复执行、记录结果并通过边界测试验证。

## 9. API 契约原则

- 管理 API 使用 `/api/admin/v1/*`；统一认证使用 `/api/v1/auth/*`；Agent 能力 API 使用 `/v1/*`。
- 所有错误包含 `code`、可展示的 `message`、`request_id`，可选 `details`；不得暴露堆栈和上游密钥。
- 列表接口定义排序、过滤、游标分页和最大 page size。
- 创建类接口支持幂等键或明确重复提交语义。
- 流式接口先定义事件格式、终止事件、客户端取消和中途失败行为。
- OpenAPI 中写清字段含义、枚举、单位、敏感性、可空性及示例。

第一里程碑至少定义：

```text
POST /api/v1/auth/login
POST /api/admin/v1/projects
GET  /api/admin/v1/projects
POST /api/admin/v1/projects/{project_id}/api-keys
GET  /api/admin/v1/projects/{project_id}/api-keys
POST /api/admin/v1/projects/{project_id}/api-keys/{key_id}/revoke

POST /v1/chat/completions

GET  /api/admin/v1/usage/summary
GET  /api/admin/v1/requests
GET  /api/admin/v1/requests/{request_id}
```

资源管理接口在对应里程碑加入，不提前实现空壳端点。

## 10. 安全与可靠性

- 所有密钥只通过服务端环境变量或密钥服务读取；提交 `.env.example`，不得提交真实 `.env`。
- 管理员用户名和密码环境变量必须同时存在或同时缺省。配置时用于创建或更新唯一管理员；缺省时使用数据库中已有管理员。只有“环境变量缺省且数据库无管理员”的首次启动必须失败。环境变量中的明文密码只用于计算密码哈希，不写入数据库或日志。
- API Key 使用密码学安全随机数生成；数据库只保存带主密钥派生的 HMAC 摘要和 Fernet 加密密文，不保存明文；API Key、摘要和密文都不得写入日志。
- 管理员密码使用适合密码的哈希算法，JWT 密钥不得使用示例默认值启动生产模式。
- 公网入口必须通过 HTTPS，配置可信反向代理、严格 CORS allowlist、请求体大小限制、登录与 Agent API 限流，并关闭面向公网的调试信息和非必要管理端口。
- 外部调用设置连接、读取和总超时；只对安全且可重试的场景有限重试。
- 代理必须正确处理客户端取消、SSE 断开和上游超时，避免连接或任务泄漏。
- 数据库查询、缓存键、统计和资源访问都必须带项目隔离条件，并使用负向权限测试验证。
- 健康检查区分进程存活与依赖就绪；不得在诊断响应中泄露连接串和密钥。

## 11. 开发阶段

每个阶段都遵循“契约 → 后端 → 后端测试 → 前端 → 端到端验收”的顺序。阶段未通过验收时，不进入下一阶段。

### P0：规格与设计（已完成）

完成产品边界、决策记录、后端架构、DI 结构、OpenAPI 基线和 UI 设计文档。

### B0：后端基础（已完成）

完成 FastAPI、类型化配置、`AppContainer` DI 注册表、PostgreSQL 适配器、Alembic 基线、健康检查和质量工具。此阶段不创建业务表，不实现前端。

### F0：前端基础

初始化 React、TypeScript、Vite、Ant Design、Zustand、路由和类型安全 API Client。完成健康检查页面和基础布局，不实现业务页面。

### A1：管理员认证

建立 `users` 表和唯一管理员约束；实现 `.env` 可选引导、数据库管理员续用、登录、JWT、退出、认证依赖和四种配置分支测试。后端接口通过后再实现登录页面。

### A2：项目管理

所有已登录用户均可创建项目，创建者成为 owner。项目支持 public/private：public 对所有已登录用户默认开放 viewer/review 权限，private 仅 owner 和已授权成员可查看；管理员对所有项目有只读 review 权限。只有项目 owner 可修改项目资料、可见性、成员角色和标签。标签可自定义，每项目最多 5 个，每个最多 20 个字符；项目列表支持关键词、标签、状态筛选和分页，并标明“我创建的”或“他人项目”。实现项目 CRUD、成员授权、项目隔离和项目详情页。完成创建、权限过滤、可见性切换、标签过滤和越权测试。
仅项目 owner 可以永久删除项目；删除前由界面二次确认，项目的标签和成员关系随项目一并删除。

### A3：API Key

一个项目可以创建多把项目级 Key，每把默认授权整个项目，可按客户端、环境或服务实例拆分，以便单独撤销和追踪。项目 owner/editor 可以随时查看完整 Key，owner 可以创建和撤销；viewer 与管理员的全局 review 权限不包含 Key 可见或管理权限。Key 使用密码学安全随机数生成；数据库使用独立 `API_KEY_SECRET_KEY` 派生 HMAC-SHA256 摘要密钥和 Fernet 加密密钥，分别用于验证与加密保存 Key。未配置至少 32 位的主密钥时，Key 管理与验证接口返回服务不可用；轮换主密钥会使已有 Key 无法解密或验证。

### A4：Mock 网关

实现服务目录、用户级 LLM 月度额度、项目额度分配、`/v1/chat/completions`、普通/SSE 响应、月度 token 预留与结算、无正文请求记录。新用户默认每月 100,000 tokens，管理员可调整个人上限；用户可将上限分配到自己的多个项目。当前只实现 LLM，不接入真实厂商。

### A5：日志与用量

实现按项目和时间范围的汇总、游标分页、日志脱敏、保留任务、Dashboard 和日志页面。统计必须与请求记录一致。

### A6：模板与记忆

实现固定目录视图、资源 CRUD、软删除、版本冲突和项目隔离，再实现目录模式与文件编辑模式。向量检索不作为本阶段前置条件。

### A7：公网部署

提供前后端 Dockerfile、Compose 和部署脚本；完成 HTTPS/反向代理、限流、CORS、备份、迁移/回滚、生产配置和关键 E2E 验收。

## 12. 验证策略

- 单元测试：业务规则、Key 校验、计价、状态转换和错误映射。
- 合同测试：OpenAPI、前端 Client、Provider Adapter 和流式事件一致。
- 集成测试：PostgreSQL、API、迁移、项目隔离和清理任务。
- E2E：只覆盖关键用户流程，避免以脆弱的 UI 测试追求覆盖率。
- 真实集成冒烟：对真实 Provider 做最小安全调用，单独报告结果。

覆盖率是辅助指标，不作为唯一质量目标。核心领域模块应有较高分支覆盖；仓库总覆盖率目标在 A1 基线建立后确定。

## 13. 非功能验收

- 所有必要命令可在干净环境按 README 执行。
- 数据库迁移可从空库升级，发布说明包含回滚或前向修复策略。
- 关键 API 有超时、错误结构和请求追踪。
- Key 撤销、项目隔离、日志脱敏和越权访问均有自动化测试。
- 前端覆盖加载、空数据、成功、失败、重试、重复提交和权限失效状态。
- 每个里程碑均记录实际运行的验证命令及结果，明确区分 Mock、代码验证和真实服务验证。

## 14. 已确定与待确定的产品决策

已确定：

1. 所有第三方集成先使用 Mock Adapter，真实 LLM Provider 和模型稍后选择。
2. 网关对公网提供服务，按公网安全基线设计和验收。
3. `.env` 可引导创建或覆盖同步唯一管理员；移除该配置后，后续启动使用数据库中已有管理员。其他用户保存在数据库中。
4. 费用币种为人民币；没有价格配置时显示 `-`，第一版主要统计 token，后续使用版本化 JSON 模型价格表。
5. 日志保留最近 30 天与全系统最新 10,000 条记录的并集。

当前默认、可由产品负责人调整：

6. 不持久化用户提示词和模型回复正文，只记录 token 数、字符数、模型、状态、延迟、错误分类和请求追踪信息。这样可以降低公网服务保存隐私、业务机密和个人信息的风险。若以后确实需要排查内容问题，应增加按项目显式开启、内容脱敏、加密、访问审计和更短保留期，不得直接复用普通调用日志长期保存全文。
