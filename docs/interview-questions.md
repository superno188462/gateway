## 实时 ASR 与协议排障

21. 实时 ASR 为什么使用 WebSocket，而非等待完整录音后调用 HTTP 文件转写？客户端、网关和火山上游各自传输什么数据？

**参考回答：** 实时场景需要客户端持续上传音频并同时接收 partial/final，故采用 WebSocket；HTTP 文件转写适合完整录音上传。客户端发 start JSON 和固定格式 PCM 二进制；Gateway 转为火山专有鉴权和帧协议，上游事件再映射为统一事件。

22. 实时接口为何限定 16 kHz、单声道、16-bit little-endian PCM？网关如何用音频帧字节数估算时长并预留额度？

**参考回答：** 固定为 16 kHz、单声道、16-bit little-endian PCM 后，每秒字节数是 16,000 × 1 × 2 = 32,000；累计字节数除以 32,000 得到音频秒数，用于额度预留。

23. 上游可能重复发送已确认语句或累计文本。`utterance_id` 和 final 去重如何工作？只按文本内容去重会出现什么错误？

**参考回答：** 网关用上游语句起始时间和说话人生成会话内稳定 `utterance_id`，记录已完成 ID，重复快照不再发送 final；累计文本路径剥离已确认前缀。只按文本去重会误删用户后来再次说出的相同句子。缺少 `start_time` 时兼容路径保证较弱。

24. 静音判停后的 utterance final 与整条 WebSocket 会话结束是什么关系？`end` 控制消息的语义是什么？

**参考回答：** 静音判停可以结束一句并产生 utterance final，但 WebSocket 会话仍可继续接收下一句；`{"type":"end"}` 表示整条输入流结束，不是单句结束。

25. 遇到 `404`、WebSocket `101` 后的 `45000000`、`45000081` 时，你会如何逐层定位？分别能证明什么、不能证明什么？

**参考回答：** HTTP 404 指向公开路径或反向代理未命中目标 WS 路由；101 只证明握手成功。`45000000` 与 EOF 对应结束帧 gzip 标记/载荷问题；`45000081` 表示等待音频超时并结束会话。Trace 用于区分公网入口、网关连接、Provider 握手、帧协议和业务事件阶段。

26. 项目记录过空结束帧的 gzip 解码错误。请说明从现象到根因的排查过程，并解释帧头压缩标记与载荷不一致为何会导致 EOF。

**参考回答：** 空结束帧载荷长度为 0，但帧头仍标 gzip，上游尝试解压空载荷后报 `ungzip payload: EOF`。修复后只有非空压缩载荷才声明 gzip；空 final 帧仍保留结束标志和负序号，但声明未压缩。材料记录了协议回归测试及定向测试结果；真实环境仍需加载新版本复测。

27. 上游等待音频超时后，能否通过持续发送静音帧保活？需要同时评估哪些费用、计量和会话状态问题？目前项目对自动重连或供应商静音计费有什么验证边界？

**参考回答：** 材料确认上游等待音频超过约 8 秒会以 `45000081` 结束会话；持续发送静音可能产生费用，不能假设免费。项目尚未实现自动暂停/重连，也未实测供应商对静音的具体计费。更详细的费用、计量及状态机评估方案，材料未说明。
