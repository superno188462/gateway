# LLM 上游连接池管理页 UI 设计

## 目标与权限

管理员在控制台管理多个 OpenAI 兼容上游连接和模型映射，并对每个连接执行连通性测试。同一个网关公开模型可以绑定多个上游连接，后端自动轮询并在网络错误、限流或上游错误时切换。普通用户不显示入口，也不能调用管理 API。供应商 API Key 只在创建或轮换时输入；保存后界面不再读取或显示明文，只显示“已配置”。

## 页面与流程

- 路由：`/admin/llm/providers`，使用现有控制台侧栏、顶栏和页面卡片视觉。
- 管理员从侧栏“LLM 供应商”进入配置列表。
- 新建上游连接：填写连接名称、Base URL、API Key；保存后为该连接添加模型映射。
- 编辑连接：可改名称和 Base URL；API Key 字段留空表示保留密钥，输入新值时轮换。可以启用或停用连接。
- 管理模型映射：填写网关公开模型名和该连接上的上游模型名。同一个公开模型名允许绑定多个连接，自动组成调用池；同一连接内公开名唯一。
- 每个连接提供“测试连通”操作，后端使用该连接的一个已启用模型发送最小 Chat Completions 请求，并记录最近测试状态、时间和安全摘要；无可用模型映射时提示先添加模型。
- 删除连接前显示确认，说明该操作同时删除连接上的模型映射；池内其他启用连接仍可继续服务。

## 页面结构

```text
LLM 上游连接池
说明：添加多个 OpenAI 兼容连接；相同网关模型名会自动组成轮询和故障切换池。

[添加连接]

模型连接池
  网关模型名: chat-standard     可用连接: 2
  ├── 连接 A / 上游模型 A / 测试成功
  └── 连接 B / 上游模型 B / 测试成功

上游连接列表
  名称       状态      Base URL       API Key       最近测试
  [测试连通] [编辑] [启用/停用] [删除]
  模型映射：公开名 → 上游名
  [添加模型]
```

连接表单字段：连接名称、Base URL、API Key。URL 使用 HTTPS；仅本机调试允许 HTTP。API Key 使用密码输入控件，不提供显示/复制按钮。模型表单字段：网关公开模型名、供应商上游模型名。公开模型名可跨连接重复，同一连接内不得重复。

## 页面状态与交互

- 初次加载显示骨架或“正在加载”；失败显示可重试错误。
- 空列表提供添加供应商主按钮及简短说明。
- 保存时禁用重复提交；成功后刷新列表并显示成功提示。
- 重名、无效 URL、缺字段等服务端错误贴近表单显示。
- 停用供应商会使其下模型暂时不能通过网关调用，但保留配置；启用后恢复。
- 删除操作二次确认；删除供应商会级联删除其模型映射。
- 测试连接显示加载状态；结果只显示成功或受控错误摘要，不显示上游响应正文或 API Key。
- 连接池按轮询选择起始连接，网络错误、限流和上游服务错误触发切换；每个请求最多尝试 3 个连接。
- 轮换密钥表单留空代表不修改；保存成功后立即清空输入框。
- 响应式布局在窄屏下改为纵向字段与模型行，保留键盘可操作的原生表单控件。

## API 契约映射

- `GET /api/admin/v1/llm/providers`：加载供应商与模型映射，只返回 `api_key_configured` 布尔值。
- `POST /api/admin/v1/llm/providers`：创建连接并提交一次性 API Key。
- `PATCH /api/admin/v1/llm/providers/{provider_id}`：更新连接配置；省略或传空 API Key 表示保留已有密钥。
- `POST /api/admin/v1/llm/providers/{provider_id}/test`：测试连接并记录最近结果。
- `DELETE /api/admin/v1/llm/providers/{provider_id}`：删除供应商及模型映射。
- `POST /api/admin/v1/llm/providers/{provider_id}/models`：新增公开名到上游名映射；不同连接可使用相同公开名。
- `PATCH /api/admin/v1/llm/models/{model_id}`、`DELETE /api/admin/v1/llm/models/{model_id}`：维护映射。
- `GET /api/v1/llm/models`：查看可调用的公开模型名。

## 安全与视觉规范

- 只为 `admin` 角色渲染入口；前端隐藏仅是展示规则，后端仍必须强制管理员鉴权。
- 页面不把 API Key 写入 URL、本地存储、日志或成功响应；切页后清除表单中的密钥。
- 供应商 API Key 与调用方的项目 API Key 是不同凭据，不使用同一展示或复制流程。
- 复用现有 `page-content`、`project-detail-panel`、`primary-button`、`secondary-button`、表单错误和成功样式，不创建新的全局视觉体系。
