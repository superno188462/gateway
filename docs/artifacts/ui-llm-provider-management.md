# LLM API 管理页 UI 设计

## 目标与权限

管理员在控制台管理多个 OpenAI 兼容上游 API 组和优先级，并对每个 API Key 单独执行连通性测试。调用方可用 `volc/doubao-seed` 指定供应商组，网关去掉前缀后将模型名原样发给上游；不带前缀时所有默认池启用 API 按优先级从小到大尝试。普通用户不能管理 API，但登录后可在“我的服务”查看当前启用的默认池和路由前缀及连接数。管理员列表按供应商、连接名、前缀和 Base URL 合并显示组信息，组内逐项显示解密后的 API Key；普通用户目录不返回任何供应商密钥。

## 页面与流程

- 路由：`/admin/llm/providers`，使用现有控制台侧栏、顶栏和页面卡片视觉。
- 管理员从侧栏“LLM API”进入配置列表。
- 新建 LLM API 组：填写供应商名称、连接名称、可选模型路由前缀和 Base URL，这些配置对组内 API Key 共用；API Key 文本框每行一个，分别保存为可独立测试、停用和删除的凭据。相同前缀的 API 组成路由组。留空前缀的连接只进入默认池。新 API 默认优先级为 100，创建时间作为相同优先级时的顺序。
- 编辑连接：可改名称、路由前缀、Base URL、优先级及 API Key；清空前缀会将连接移出指定供应商组，优先级数值越小越先调用。API Key 字段留空表示保留密钥，输入新值时轮换。可以启用或停用连接。
- 每个连接提供模型名输入框和“测试连通”操作。管理员输入该上游实际支持的模型名，后端用它发送最小 Chat Completions 请求，并记录最近测试状态、时间和安全摘要。
- 删除连接前显示确认；其他启用连接仍可继续服务。

## 页面结构

```text
LLM 上游连接池
说明：添加多个 OpenAI 兼容连接；可以配置前缀组，组内按优先级故障切换。

[添加连接]

上游连接列表
  名称       前缀      状态      优先级       Base URL       API Key       最近测试
  测试模型名 [测试连通] [编辑] [启用/停用] [删除]
```

连接组表单字段：供应商名称、连接名称、可选路由前缀、Base URL 和多行 API Key。每行密钥独立创建一条可单独测试和管理的 LLM API 记录，组字段在这些记录间保持一致。供应商名称面向用户展示；连接名称帮助管理员识别一组 API。前缀会统一转成小写，只允许英文字母、数字、连字符和下划线，且以字母开头；URL 使用 HTTPS，仅本机调试允许 HTTP。API Key 使用密码控件，不提供显示/复制按钮。带前缀时必须存在同名前缀的启用连接，否则请求返回模型不存在；前缀匹配不区分大小写，上游收到去掉前缀后的模型名。未带前缀时模型名原样传给全局连接池。

## 页面状态与交互

- 初次加载显示骨架或“正在加载”；失败显示可重试错误。
- 空列表提供添加供应商主按钮及简短说明。
- 保存时禁用重复提交；成功后刷新列表并显示成功提示，已保存的密钥在管理员列表明文展示并可复制。
- 重名、无效 URL、缺字段等服务端错误贴近表单显示。
- 停用供应商会使该连接暂时不参与调用，但保留配置；启用后恢复。
- 删除操作二次确认；删除只移除该连接。
- 测试连接显示加载状态；结果只显示成功或受控错误摘要，不显示上游响应正文或 API Key。
- 每次调用都从优先级最高的启用连接开始；网络错误、400/401/403/404/408/409/422/429 和 5xx 会尝试下一连接；其他 4xx 直接返回，所有尝试线路都失败后网关返回可诊断的错误。
- 测试模型名为临时输入，仅用于该次测试；不作为模型映射或调用白名单。
- 连接测试针对具体连接，测试输入使用供应商原始模型名，不添加路由前缀。
- 轮换密钥表单留空代表不修改；保存成功后立即清空输入框。
- 响应式布局在窄屏下改为纵向字段与模型行，保留键盘可操作的原生表单控件。

## API 契约映射

- `GET /api/admin/v1/llm/providers`：按优先级加载每条 LLM API，仅管理员可访问；返回可查看的明文 API Key 和 `api_key_configured` 状态。
- `POST /api/admin/v1/llm/providers`：创建一条连接凭据并提交一次性 API Key；组内多密钥由前端逐条调用。
- `PATCH /api/admin/v1/llm/providers/{provider_id}`：更新连接配置、路由前缀和优先级；省略 API Key 表示保留已有密钥。
- `POST /api/admin/v1/llm/providers/{provider_id}/test`：提交临时模型名测试连接并记录最近结果。
- `DELETE /api/admin/v1/llm/providers/{provider_id}`：删除供应商连接。
- `GET /api/v1/llm/models`：只列出网关内置模型。动态上游模型不能在不查询上游模型列表的情况下枚举，调用方可直接传入供应商模型名。
- `GET /api/v1/llm/provider-catalog`：登录用户读取启用路由组、去重的供应商显示名称及连接数量；不暴露连接名、URL、优先级或密钥。用户在“我的服务”页可以查看供应商名称和可用前缀，并按 `前缀/模型名` 调用。

## 安全与视觉规范

- 只为 `admin` 角色渲染入口；前端隐藏仅是展示规则，后端仍必须强制管理员鉴权。
- 页面不把 API Key 写入 URL、本地存储或日志；管理员接口响应会包含密钥明文以支持管理查看，普通用户 API 不返回密钥；添加表单提交后清除输入框。
- 供应商 API Key 与调用方的项目 API Key 是不同凭据，不使用同一展示或复制流程。
- 复用现有 `page-content`、`project-detail-panel`、`primary-button`、`secondary-button`、表单错误和成功样式，不创建新的全局视觉体系。
