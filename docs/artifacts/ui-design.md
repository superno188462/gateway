# 管理控制台 UI 设计（P0）

本文件记录控制台 UI 设计基准；实现状态以 `docs/status.md` 为准。

## 用户与核心任务

- 管理员：查看全局项目、调用状态、token 用量和日志；配置服务。对项目的全局权限为只读 review。
- 普通用户：创建项目，查看本人创建、公开或已加入的项目，并按项目角色操作；查看可访问项目的调用和用量。

核心路径：登录 → 选择项目 → 创建或撤销 Key → 查看调用与 token → 管理项目资源。

## 信息架构与路由

```text
/login
/projects                 项目列表
/projects/new             创建项目（独立页面）
/projects/:projectId      项目概览
/projects/:projectId/keys API Key
/services                 服务概览与个人额度
/services/llm/projects    已开通 LLM 服务的项目
/                         Dashboard（按项目筛选用量）
/admin/logs               管理员全局操作日志
/admin/system-logs        管理员技术日志
/projects/:projectId/logs 项目操作日志
/projects/:projectId/resources 记忆与模板目录
/users                    普通用户管理（权限确定后实现）
```

登录页独立布局。登录后的桌面布局为左侧导航、顶部项目切换与账户区、右侧内容区。窄屏收起导航，但数据表允许横向滚动，不为移动端牺牲关键字段。

## 页面布局

### Dashboard

顶部为项目和时间范围筛选；下方展示调用次数、成功率、token 用量、平均延迟、费用卡片，以及按日趋势和模型分布。费用为 `null` 时展示 `-`，不得显示为零元。管理员汇总全局记录，普通用户只汇总其可访问项目。

### 个人服务与额度

用户从左侧“服务”父项或“LLM”子项进入 `/services` 或 `/services/llm`。页面按服务展示用户级月度上限、已分配到本人项目的总额度、剩余可分配额度和当月实际用量。每项服务的“管理项目”进入对应服务已开通项目列表，而不是通用项目列表；项目列表按权限过滤并由后端分页。新注册用户默认获得统一的 LLM 上限，管理员可调整个人额度。后续增加 ASR、TTS 等服务时按接口返回的服务目录扩展，不预留空卡片。

管理员在同一页面额外看到“用户 LLM 额度管理”区，可选择按唯一用户名精确匹配或按 UUID 查找。找到用户后先展示用户名、用户 ID、角色、当前月上限、项目已分配额度和当月用量，再编辑新的月上限并保存。查询未命中、输入无效时保留查询条件并显示可读错误；保存成功后显示更新后的汇总。管理员可以把上限调到低于项目分配总额，项目分配记录保留，用户调用始终受个人总上限限制；设为 0 时暂停该用户的服务调用。

个人服务页在“项目分配总额高于个人上限”或“个人额度为 0 但项目仍有分配”时显示醒目的提醒，说明实际调用按个人上限限制或已暂停，并建议联系管理员或协调项目额度。项目详情页的 owner 也会看到该提醒。

用户进入自己拥有的项目详情，为项目申请 LLM 服务并设置该项目月度 token 上限。页面需显示个人可分配余额；提交时后端再次校验，确保本人所有项目的分配总和不超过用户上限。项目用量与个人跨项目用量都按 UTC 自然月统计。管理员只读 review，不通过全局管理员身份代用户分配项目额度。

页面状态包括：无额度（管理员将额度设为 0 时解释联系管理员）、额度未分配、部分已分配、全部已分配、正在申请/调整、个人上限不足、申请冲突、服务不可用和会话失效。配额降低时保留已产生用量，不能把项目上限调到低于当月已用加预留 tokens。

### 项目与 Key

项目列表默认筛选“运行中”；用户可切换为“所有状态”或“已停用”，清除筛选后恢复默认值。
项目详情页仅对 owner 显示“删除项目”操作；删除前明确确认不可撤销，管理员的跨项目 review 权限不包含删除权限。

所有已登录用户都可以创建项目，创建表单可选择公开或私有（默认私有），并填写可选标签。标签由 owner 自定义，每项目最多 5 个、每个最多 20 个字符；输入时 trim 并按小写规范化，过滤器支持对已有标签模糊搜索并提供匹配建议。项目列表支持名称/描述关键词、标签、状态过滤和服务端分页，只显示当前用户有权查看的项目；列表和详情页按 `owner_id` 标明“我创建的”或“他人项目”，区分本人项目与公开 review 项目。点击项目进入独立详情路由 `/projects/:projectId`。管理员可 review 全部项目，但只有项目 owner 能编辑资料、标签和成员权限。公开项目对所有已登录用户提供只读 review；私有项目仅 owner 和显式授权成员可查看。Owner 可按唯一用户名或用户 UUID 添加成员并指定 `editor` / `viewer`，调整非 owner 成员角色、查看成员用户名与 UUID，或移除非 owner 成员。owner/editor 均可创建和管理本人的 API Key；Key 页面只列出当前登录成员创建的密钥。

### API Key 管理（A3）

路由为 `/projects/:projectId/keys`，从项目详情页进入。owner 和 editor 始终可以看到该入口并查看项目 Key 元数据；owner 可以创建和撤销 Key，editor 只读。viewer 和无项目成员身份的管理员不显示入口。页面顶部显示项目名和返回项目链接。创建表单包含 Key 名称和有效期（永不过期、30 天、90 天或 365 天）。

创建表单包含 Key 名称和有效期（永不过期、30 天、90 天或 365 天）。创建成功后显示完整 Key，并可一键复制；列表对 owner/editor 始终显示完整 Key，也显示名称、状态、创建时间、过期时间和最近使用时间。Key 不写入浏览器本地存储；服务端使用配置密钥加密持久化，绝不返回摘要。撤销前二次确认；撤销和过期记录仍显示原 Key 供识别，但不可继续调用。

页面状态包含加载、无 Key、创建/撤销中、创建成功、权限不足、配置缺失、会话过期及请求失败后重试。所有异步操作禁用重复提交；密钥不得写入 localStorage、sessionStorage、URL 或日志。

### 项目操作日志

所有有权查看项目的成员（owner、editor、viewer）均可从项目详情查看该项目操作日志；管理员从 `/admin/logs` 查看全局操作日志并可按项目筛选。日志统一包含服务调用与项目管理操作，按项目 ID 授权并由数据库分页。项目操作包括项目资料、成员权限、API Key、服务额度及模板/记忆资源的管理；记录操作者、动作、结果和 Trace ID，不保存模板正文、提示词、模型回复或凭据。服务调用继续展示面向用户的错误码与原因、token 用量及延迟，不返回内部审计步骤、额度计算细节或上游异常。管理员可查看最近日志保留任务结果并手动执行保留任务。

管理员技术日志与项目操作日志分开显示，按时间、等级、来源、Trace ID 和事件内容展示技术日志，支持按等级、Trace ID 和事件文本筛选。页面打开时读取一次，之后只有管理员手动刷新、提交筛选或切换页码时才读取。技术日志来自后端按日轮转的运行日志文件，接口按页返回匹配总数和页数，每次只返回一页；每次最多扫描当前日志文件尾部 5,000 行。技术日志记录认证、API Key 所属成员 ID/用户名、路由、额度决策（限额、已用、预留、请求预留量）、上游尝试和异常诊断；只有管理员可以打开该页面和调用对应接口。两类日志使用同一个 Trace ID 关联。

项目 API Key 按成员个人归属。项目 owner/editor 均可创建、查看和撤销自己的 Key；不能查看或撤销其他成员的 Key。每把 Key 仍授权整个项目。成员角色降为 viewer 或被移出项目时，系统在同一事务中撤销该成员在此项目下的有效 Key。

### 服务导航与项目上下文

左侧导航将可点击的“服务”作为父级，子项“LLM”和“上下文管理”可折叠显示。服务父项进入 `/services`，LLM 打开 `/services/llm`；上下文管理打开 `/services/context`。两类服务项目页只展示当前用户可查看且已启用对应服务的项目，并由后端分页；管理员可查看全部已开通项目。项目卡片区分“我创建的项目”和“我可访问的项目”，上下文项目分别链接到 `/services/context/:projectId/templates`、`/short`、`/long`、`/profile` 四个独立页面。项目详情保留快捷入口，旧 `/projects/:projectId/context` 路由作为兼容入口。

提示词模板页通过登录态资源 API 管理模板，owner/editor 可新增、修改、软删除，viewer 和管理员只读。模板字段包括项目内唯一名称、分类、正文和版本；正文可含调用方占位符，但首版网关原样存取，不负责变量渲染。Swagger UI 的 Project Resources 和 Project Context Gateway 分类都提供可执行请求示例；运行时可以按模板 ID 或分类/名称读取，项目由 API Key 确定。

短期记忆页按 `external_user_id + session_id` 查询会话消息，显示 role、正文和顺序；owner/editor 可以通过项目 API Key 追加消息。网关不会自动过期或清除数据，只有显式删除 API 会清除；页面明确提示长期保留。读取默认最近 50 条，最多读取 100 条。原有短期 key/value 接口保留兼容。长期记忆页按 `external_user_id` 管理跨会话文本条目及标签/元数据；画像页按 `external_user_id` 管理项目自定义 JSON，不要求统一 schema。后两类写入沿用 API Key 运行时接口和版本检查。

动态上下文控制台查询通过 JWT 管理接口，不要求用户在浏览器中读取或暴露 API Key。项目 owner/editor 可以查询；viewer 和公开项目访客不能查用户动态数据；管理员可跨项目只读查询，写操作仍拒绝。项目 API Key 运行时接口继续服务外部 Agent。Key 可见性规则保持 owner/editor 可见；管理员查询由服务端按管理权限执行。

页面状态覆盖项目列表分页、空项目、未开通服务、消息为空、画像尚未创建、JSON 无效、Key 不可用、只读权限、登录失效、版本冲突和网络错误。短期消息不保存到技术日志或通用调用日志正文。所有上下文数据按 `project_id` 隔离；运行时项目 ID 从 API Key 解析，长期数据再按外部用户 ID 隔离，会话消息另按 session ID 隔离。

页面操作映射到 `GET /api/admin/v1/context/projects`、`GET /api/admin/v1/context/projects/{project_id}/permissions`、现有 Project Resources 管理 API、JWT 控制台只读 API，以及 `/v1/context/templates`、`/messages`、`/memories`、`/profile` 项目 API Key 运行时接口。

## 状态设计

每个远程页面必须覆盖：

- 初始加载：骨架屏或局部加载，不闪现错误空态。
- 空数据：解释原因并提供唯一主要操作。
- 成功：列表原位更新，关键创建操作有明确反馈。
- 可恢复错误：保留筛选或表单内容，提供重试。
- 不可恢复错误：展示 request_id，隐藏后端堆栈。
- 登录失效：清理敏感内存状态并返回登录页。
- 重复提交：请求期间禁用提交按钮。
- 页面切换和取消：旧响应不得覆盖新页面状态。

## 可访问性与响应式

- 所有表单有可见标签、字段错误和键盘焦点。
- 弹窗打开后管理焦点，关闭后返回触发元素。
- 状态不能只依赖颜色；图表提供文字摘要或表格替代。
- 主要操作可用键盘完成，交互控件使用语义化元素。
- 桌面优先，最小支持 768px；更窄屏幕保留查询和应急操作能力。

## 页面到 API 映射

| 页面 | API 阶段 |
|---|---|
| 登录 | A1 `/api/v1/auth/login`，登录后按角色进入可访问页面 |
| 项目 | A2 项目 CRUD、按用户名或 UUID 管理成员 |
| API Key | A3 Key 创建、列表和撤销 |
| 个人服务与额度 | A4 当前用户服务能力、用户级月上限、跨项目分配汇总和实际用量 |
| Dashboard / 日志 | A4–A5 用量汇总和请求查询 |
| 模板与记忆 | A6 资源目录和文件 CRUD |
| ASR API 与服务额度 | A8 管理员上游配置、用户/项目秒额度、文件转写与实时 WebSocket 接入 |

前端只通过 OpenAPI 生成的共享 Client 调用接口。契约未定义的页面操作不得自行猜测字段。
