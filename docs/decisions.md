# 项目决策记录

## D-001：第三方能力先使用 Mock

- 状态：历史阶段决策（已由 D-017 扩展）
- 决策：LLM、Embedding、ASR、TTS 等第三方接口先通过可替换的 Mock Adapter 完成契约、界面和端到端流程。
- 原因：真实供应商和模型尚未选定，不应阻塞核心网关能力，也不应让供应商 SDK 渗透业务层。
- 说明：此决策记录了早期阶段的实施顺序。A4 LLM 上游和 A8 ASR 已按后续阶段接入真实 Provider；Mock Adapter 继续用于自动化测试。

## D-002：网关暴露公网

- 状态：已决定
- 决策：Agent API 和管理控制台均按公网服务设计。
- 影响：生产入口必须使用 HTTPS，并落实反向代理信任边界、CORS allowlist、限流、请求大小限制、敏感信息脱敏和非必要端口关闭。

## D-003：唯一管理员支持环境变量引导和数据库续用

- 状态：已决定
- 决策：管理员用户名和密码环境变量必须同时配置或同时缺省。两项均配置时，应用以事务方式创建或覆盖同步数据库中的唯一管理员；两项均缺省时，直接使用数据库已有管理员，不修改账号信息。
- 首次启动：环境变量缺省且数据库没有管理员时启动失败，并提示配置管理员引导信息。只配置用户名或只配置密码时也启动失败。
- 持久化：管理员成功写入数据库后可以移除 `.env` 中的管理员配置，后续启动继续使用数据库记录。密码只保存安全哈希。其他用户通过业务流程写入数据库。
- 约束：数据库必须保证最多一个管理员。发现异常的多个管理员且无法安全自动修复时，应用启动失败并输出不含敏感数据的诊断。

## D-004：费用暂不作为第一版核心指标

- 状态：已决定
- 决策：第一版重点展示 token 消耗。币种为人民币，没有价格配置时 API 返回 `null`、前端显示 `-`。
- 后续：使用版本化 JSON 价格表配置不同模型的计价单位与价格，调用时保存价格版本和费用快照。

## D-005：日志保留采用时间和数量的并集

- 状态：已决定
- 决策：保留所有最近 30 天的日志，同时保证全系统最新 10,000 条日志始终保留。
- 示例：最近 30 天有 6,000 条，则继续向前保留到 10,000 条；最近 30 天有 50,000 条，则 50,000 条全部保留。

## D-006：通用操作日志与服务专属用量分离

- 状态：建议默认，等待产品负责人需要时调整
- 决策：通用操作日志统一记录服务调用与项目管理操作，保存项目/Key 归属、事件类型、状态、耗时、错误分类、追踪标识和可读描述；不保存用户提示词或服务回复正文。模型、Token 等服务专属数据由对应服务自己的数据表保存。
- 原因：提示词和回复可能包含个人信息、账号数据、源代码、合同内容或其他业务机密。公网网关长期保存全文会增加泄露和合规风险。
- 实现：`gateway_requests` 保存通用调用记录；LLM 使用 `llm_request_usages` 保存模型、Token 用量和结束原因。用户看到的服务结果说明是普通文本，不要求所有服务使用同一组专属字段。
- 后续：若需要内容调试，设计按项目显式开启的短期诊断功能，并加入脱敏、加密、访问审计和独立保留期。

## D-007：本地开发不依赖 Docker

- 状态：已决定
- 决策：本地开发分别运行服务；后端使用 `uv run python main.py`，前端在 F0 完成后使用 `npm run dev`。
- Docker：仅提供服务器部署所需的 Dockerfile、Compose 和配置脚本，本机测试不以 Docker 为前置条件。

## D-008：统一认证入口，按角色授权

- 状态：已决定
- 决策：普通用户和管理员统一通过 `/api/v1/auth/*` 完成认证；JWT 携带角色标签。平台级管理接口可要求 `role=admin`；项目等资源操作按项目可见性、成员关系和 owner 身份授权，不因全局 admin 角色自动获得写权限。
- 原因：认证负责确认身份，授权负责判断权限，不能用不同登录 URL 固化角色边界。
- A1 范围：当前只实现唯一管理员引导；普通用户记录和普通用户权限将在后续阶段接入同一套认证流程。

## D-009：项目创建、可见性与管理员审阅权限

- 状态：已决定
- 决策：所有已登录用户都可以创建项目，创建者自动成为项目 owner。项目默认私有，也可以设置为公开。公开项目对所有已登录用户开放只读 review 权限；私有项目对 owner 和显式加入的成员开放。管理员可以 review 所有项目，但全局管理员身份本身不授予编辑或成员管理权限；管理员若是项目 owner，则按该项目的 owner 权限管理。
- 实现：公开项目使用可见性规则授予只读访问，不为每个用户创建冗余成员关系；成员表仅保存 owner 和显式授权成员。

## D-010：项目标签与列表检索

- 状态：已决定
- 决策：项目标签由 owner 自定义，不设封闭的固定标签集合；每项目最多 5 个标签，每个最多 20 个字符。写入时去除首尾空格、统一小写并在项目内去重。界面展示已有标签建议，允许 owner 新增自定义标签。
- 检索：项目列表提供关键词、标签和状态筛选，并使用服务端分页。查询始终先按公开/私有和用户成员权限过滤；管理员只对其可 review 的结果进行筛选。
- 数据：使用 `project_tags` 关联表保存标签，支持索引和精确匹配；未来若需要固定业务统计维度，再单独增加分类字段。

## D-011：项目级 API Key

- 状态：已决定
- 决策：一个项目可以有多把 API Key；每把 Key 仅归属于创建它的 owner/editor，但默认具有整个项目的调用权限，不在 A3 为单个服务设置 scope。创建者只能查看和撤销本人 Key；成员降为 viewer 或移除时自动撤销其项目 Key。
- 用途：允许不同客户端、部署环境或服务实例各自使用独立 Key，便于单独撤销和后续追踪。
- 可见性和权限：项目 owner/editor 始终可查看完整 Key；仅 owner 可以创建和撤销。viewer 和管理员的全局 review 权限不包含 Key 可见或管理权限。
- 安全：Key 使用密码学安全随机数生成；数据库保存 HMAC-SHA256 摘要用于验证，并保存 Fernet 加密密文供 owner/editor 授权查看。明文不落库。
- 配置：`API_KEY_SECRET_KEY` 至少 32 个字符，用于派生摘要和加密密钥。未设置时 Key 管理和验证关闭；生产环境不得轮换该值，否则现有 Key 将无法解密或验证。
- A4：每个服务目录项独立申请；API Key 仍授权整个项目，网关从 Key 解析项目后检查该项目是否开通目标服务，并从 Key 读取成员归属用于审计。

## D-012：A4 LLM Mock 用户级额度与项目分配

- 状态：已决定（Mock 阶段）
- 决策：用户先获得服务级月度 token 总上限，再由其为自己拥有的项目分配额度。项目申请后自动开通，无人工审批或支付；调用端只传项目 API Key 和模型请求，不传项目 ID。
- 用户默认额度：新注册用户的 `mock-llm-v1` 默认每 UTC 自然月 100,000 tokens，可通过 `DEFAULT_LLM_MONTHLY_TOKEN_LIMIT` 调整新用户默认值；管理员可按用户名或用户 ID 调整既有用户额度。额度设为 0 会暂停该用户此服务的调用，既有项目分配记录保留。
- 分配约束：项目 owner 申请或调整项目分配时，所有项目分配总和不得超过当前用户上限；管理员可把用户上限调低到项目分配总和以下，项目分配记录不自动更改，网关同时执行用户总上限。个人服务页和项目详情须提醒用户额度不足或服务暂停。项目额度不得低于本月已使用加预留 tokens。管理员只读 review 项目，但可以配置用户账户级服务额度。
- 调用：提供 OpenAI 风格 `POST /v1/chat/completions`，支持 JSON 与 SSE。模型标识为 `mock-chat`，当前 Mock Provider 不连接真实厂商。
- 用量：项目请求同时受项目分配额和用户跨项目总上限约束。预留 prompt token 估算值加 `max_tokens`，成功后以 Provider 返回用量结算，多余预留释放；项目和用户用量按服务、UTC 月汇总。超额请求返回 429。
- 隐私与日志：通用网关请求表不包含模型或 Token 字段；LLM 模块独立保存模型与 Token 计量，不保存用户消息和模型回复正文。Mock tokenizer 是粗略估值，接入真实 Provider 后以供应商 usage 为准。
- 后续：用户等级与各服务上限可演进成平台套餐/运营配置；ASR、TTS、Embedding、RAG、记忆和画像不在本阶段实现。

## D-013：项目模板与记忆资源

- 状态：已实现（A6）
- 决策：模板和记忆是项目隔离的数据库资源，固定目录仅作为类型与分类视图，不对应服务器文件路径。资源按项目、资源类型、固定分类和名称区分；删除采用软删除，允许后续用相同名称新建。资源正文仅在用户明确保存后进入资源表，与调用日志正文分离。
- 权限：管理员凭全局身份跨项目只读；项目 owner/editor 可写；viewer 和公开项目访客只读。管理员若是项目的明确 owner/editor 成员，按成员角色授权。
- 并发：更新与软删除都提交预期版本；成功后递增版本，版本已变化时返回 `409 version_conflict`，不覆盖其他人的修改。

## D-014：AI 推理额度与项目上下文服务分离

- 状态：已决定
- 决策：项目级月度额度用于有 AI 推理/生成消耗的服务，包括 LLM、Embedding、RAG、TTS 和 ASR；不同服务可以采用各自合适的计量单位，不能假设一律按 LLM tokens 结算。RAG 若组合多个模型步骤，应在服务契约中明确由哪些底层用量组成，避免重复计量。
- 项目上下文服务（提示词模板、短期记忆、长期记忆、用户画像及后续项目资源）是独立的项目级数据服务，通过项目申请和订阅门禁控制使用；它本身不扣 AI 推理额度。存储容量、请求频率等资源保护限制属于独立服务配置，不计入 AI token 额度。
- 兼容性：当前 `mock-llm-v1` 的 token 配额行为保持不变。ASR 已通过 `asr-v1` 独立服务按音频秒数计量；后续为 Embedding、RAG、TTS 扩展服务目录时，再按各自计量单位扩展配额契约。不得把 LLM 的 token 字段直接套用到上下文存储服务。

## D-015：项目上下文运行时 API 与存储隔离

- 状态：已实现（A6）
- 决策：项目上下文作为 `app/services/project_context` 独立服务模块注册到服务目录。项目 owner 申请即开通，订阅不带 token 上限；无订阅或订阅暂停时，运行时 API 拒绝访问。
- 认证和边界：调用方只发送项目 API Key。网关从 Key 解析 project_id，不接受客户端指定项目 ID；模板、短期记忆、长期记忆、画像的每次查询都必须以该项目 ID 作为第一层过滤，再以模板名称或外部用户/会话标识作为二级范围。
- 能力：模板由项目成员在控制台管理并由接入应用读取；短期记忆按 external_user_id、session_id、memory_key 唯一定位，网关不自动过期或清理；长期记忆按项目用户分页、标签和版本更新；用户画像按项目用户存储 JSON 并使用乐观版本。
- 隐私：调用正文不写入技术日志或通用调用日志；仅记录项目、服务码、状态、错误分类、耗时和 Trace ID。上下文内容是项目数据，由项目成员通过已授权控制台资源 API 管理。
- 操作日志：项目操作日志与服务调用使用同一套分页和权限查询，按事件类型区分；项目成员（包含 viewer）可查看项目范围内的事件，管理员可以查看全局。模板、成员、API Key、额度等变更只记操作者与脱敏元数据，不记资源正文或密钥。LLM 用量汇总仅计算服务调用事件。
- API Key 归属：每把项目 Key 只归属于创建它的 owner/editor。用户仅能查看和撤销自己的 Key；角色降为 viewer 或被移出项目时，该成员在项目中的所有有效 Key 自动撤销。服务调用记录 API Key ID、成员 ID 和用户名，供操作日志与技术日志追查。迁移前创建的共享 Key 统一归属项目 owner。
- 配额：上下文存储服务不进入个人 AI token 配额列表，也不受模型 token 预留/结算路径影响。存储容量和请求频率是独立的服务保护策略；当前不设置自动过期或定时删除。

## D-016：上下文数据形态与控制台入口

- 状态：已决定
- 导航：侧边栏“服务”作为父级，所有登录用户都可直接进入 LLM 和上下文管理服务。上下文入口先分页列出当前用户可查看且服务已启用的项目，再按模板、短期记忆、长期记忆和画像分开页面管理。
- 短期记忆：这是接入项目的功能名称，不代表网关保存时长。标准会话数据是多条 `role/content` 消息，按追加顺序保存；网关不会因时间或缺少 API 调用而自动删除，仅显式删除 API 会清除数据。原有 key/value JSON API 保留兼容。默认读取最近 50 条，单次最多 100 条。
- 长期记忆：保存项目自行提炼的文本条目，标签和 metadata 为可选元数据；首版不要求 RAG 或向量检索。
- 用户画像：由项目定义任意 JSON 对象，网关不设固定业务 schema；唯一范围为 `project_id + external_user_id`。
- 权限：运行时接口使用项目 API Key，项目 ID 仅从 Key 解析。控制台的动态数据读取使用登录态 API 校验项目权限，owner/editor 可读写，viewer 不可查询，管理员跨项目只读；管理员不需要查看项目 API Key。
- 模板：通过控制台登录态 API 创建和维护，运行时 API Key 按 ID 或分类/名称读取。首版正文原样返回，变量由调用项目处理。Swagger UI 的请求 schema 提供可直接测试的实例。

## D-017：A8 火山豆包 ASR 网关

- 状态：已实现并通过用户自测
- 决策：ASR 作为独立 `asr-v1` 服务纳入阶段 A8，当前接入火山引擎豆包 Seed ASR 2.0。管理员在网关配置火山密钥、Resource ID、文件转写 URL 和实时流 URL；调用方只使用项目 API Key、网关地址和公开模型名。
- 计量：ASR 按识别音频秒数执行用户总额度与项目额度的预留和结算，不消耗 LLM token 额度。
- 实时协议：网关接受 JSON 控制消息及 16 kHz 单声道 s16le PCM 二进制帧，将火山上游事件转换为统一 partial/final/error 事件。final 包含稳定 `utterance_id`，重复投递按 ID 去重；静音判停完成语句不结束整个客户端 WebSocket，`end` 只结束完整音频流。
- 隐私：日志保留 Trace ID、成员、状态、错误分类和耗时，不记录 API Key、音频或转写正文。

## D-018：Embedding 与 RAG 知识库首版

- 状态：已决定；A9 后端首版实现中。
- Embedding：管理员上游连接配置遵循 LLM 的 OpenAI 兼容 Base URL、加密 API Key、模型前缀路由、同组优先级故障切换；调用方使用项目 API Key 调用 `/v1/embeddings`。首批仅实现文本模态，独立 `embedding-v1` 按上游 token usage 结算。
- 多模态：图像、视频嵌入能力由各上游模型和协议决定，不能假定任意 OpenAI 兼容 Embedding API 都接收媒体。后续通过显式模型能力声明和供应商适配器扩展；媒体上传及原文件对象存储待选定供应商后设计。PostgreSQL 中预留 modality、model 和 dimensions 字段。
- RAG：使用现有 PostgreSQL 安装 pgvector 扩展，项目级隔离知识库、文档、切片、元数据和向量。首版知识库固定 Embedding model，首次嵌入确定维度，切换维度需要新建知识库并重嵌。服务返回 top-k 片段，由业务调用方决定如何构造 LLM Prompt，不在 RAG 服务里重复调用生成模型。
- 计量和门禁：Embedding 服务按 tokens 使用独立用户/月额度及项目分配额度。RAG 知识库是单独服务订阅；写入和检索内部消耗的模型 token 记入 `embedding-v1`，避免再重复收取 RAG tokens。
- 检索：首版使用 pgvector cosine distance 精确检索，知识规模和维度模式稳定后再按数据规模增加 HNSW/IVFFlat 索引并执行召回验证。
- 隐私：通用日志仅记录项目、API Key 成员归属、模型、token 用量、Trace ID、结果及错误，不记录输入正文、原始媒体或向量内容。RAG 知识正文按项目业务数据保存在 PostgreSQL。
